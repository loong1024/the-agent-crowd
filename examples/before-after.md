# 对照案例:多 agent 代码评审放过了同一个 bug

场景:实现 agent 交付了一个带边界条件 bug 的解析函数(输入为空时提前 return,上游状态残留),编排者随后派三个评审 agent 复审。同一种评审有两种派法,结果如下。

## 两栏对照

| 维度 | Before:乌合之众式 | After:the-agent-crowd 式 |
|---|---|---|
| 评审者与实现者的关系 | 同一模型家族,先验与盲区相同 | 不同模型通道,先验独立 |
| 评审者拿到的上下文 | 作者的实现说明 + 完整会话历史 | 只有工件与验收标准,零上下文冷审 |
| 作者 / 模型身份 | 已知(资深作者,评审默认放行) | 已剥离,盲审 |
| 派发词 | 「我觉得差不多了,帮忙再确认一下」 | 「审查 <file> 是否满足 <spec>,仅此而已」 |
| 评审者之间 | 共享群聊,先发言者定调 | 互相隔离,各自私下出结论 |
| 票数口径 | 三个 agent 记三票 | 两个同源记一票,合计两票 |
| 证据要求 | 「报告一下是否通过」 | 每条结论必须带 file:line 或命令输出 |
| 结论形式 | 裸 ✅ all passed | 分级 pass / fail / blocked / skipped / unverified |
| 异议处理 | 质疑者被两票压下,异议未记录 | 异议原文引用进合并报告,写明是否推翻 |
| 结果 | bug 漏网,全绿报告,三天后线上报障 | 同一 bug 在冷审被抓,file:line 定位,当场修复 |

## 差别的本质

差别的本质是**独立性**,不是 agent 数量。Before 的三个评审在统计意义上只是一个评审:同源先验、共享上下文、被同一句派发词锚定,N 是假的。After 的评审哪怕只派一个,冷审 + 盲审 + 证据强制也大概率能抓住同一个 bug;数量带来的复利——Condorcet 条件(每人正确概率过半且互相独立)——只在独立性成立之后才开始生效。把「多派几个 agent」换成「多制造一个独立的判断」,这就是本仓库的全部内容。
